# Charts — Agent Guide

This document provides guidance for AI coding agents (GitHub Copilot, Codex,
Claude, etc.) working in this repository.

---

## Git Workflow — MANDATORY

- **Never commit changes** unless explicitly instructed to do so.
- **Never create a branch** unless explicitly instructed to do so.
- **Never open a pull request** unless explicitly instructed to do so.
- Leave all changes as unstaged working-tree modifications by default.

---

## Shell Environment

This repository uses [**mise**](https://mise.jdx.dev) (`mise.toml`) to provide
the required tooling.

**Always run bash commands through mise-managed tools.** After installing mise
and trusting the repo (`mise trust && mise install`), the tools defined in
`mise.toml` are available directly on `PATH` via mise's shims/activation, so
commands can be run as-is:

```bash
ct lint --config ct.yaml
ct install --config ct.yaml
go test ./...
```

If mise is not activated in your shell, prefix commands with `mise exec --`:

```bash
mise exec -- ct lint --config ct.yaml
mise exec -- ct install --config ct.yaml
mise exec -- go test ./...
```

Do **not** assume system-installed versions of `go`, `helm`, `ct`, `kind`, or
any other tool — they may be absent or wrong. All tools must be resolved
through mise.

`mise.toml` provides:
- **Go 1.26** (`go`, `gofmt`) for the internal updater module
- **Helm** (`helm`) and **helm-docs** for chart packaging and README generation
- **helm-ct** (`ct`) for local chart lint/install checks matching CI
- **kind** and **kubeconform** for validation/test clusters
- **golangci-lint** for the Go helper code under `internal/`
- **yamllint** for YAML validation

## Project Overview

This repository defines and publishes Helm charts to
`https://cloudhippie.github.io/charts`.

Most repository content lives under `stable/` as chart sources. A small Go
module under `internal/` powers the scheduled version update workflow:
`internal/cmd/updater` scans chart directories, looks up newer OCI image/chart
versions, rewrites `Chart.yaml` / `values.yaml`, and bumps chart versions when
upstream app or dependency versions change.

## Repository Layout

```text
stable/
  <chart>/
    Chart.yaml           # Chart metadata, dependencies, chart version
    values.yaml          # Default values; updater annotations may live here
    templates/           # Rendered Kubernetes manifests
    README.md            # Generated by helm-docs
    source.yaml          # Upstream image metadata for the updater

internal/
  chart/                 # Chart discovery, OCI lookup, version bump helpers
  cmd/updater/           # `go run ./internal/cmd/updater .`

go.mod                   # Go module for internal tooling
ct.yaml                  # chart-testing configuration
cr.yaml                  # chart-releaser configuration
README.md                # Public repository overview
mise.toml                # Tool versions for local chart work
```

## Chart Development

- Each chart lives in its own directory under `stable/<chart>/`.
- Treat `Chart.yaml` as the source of truth for `version`, `appVersion`, and
  chart dependencies.
- Keep default values and any updater annotations in `values.yaml`.
- When a chart README is derived from chart metadata/values, regenerate it with
  `helm-docs` so the checked-in documentation stays in sync.
- The `helmdocs.yml` workflow updates `stable/**/README.md` automatically on
  pushes to `master`, but local changes should still regenerate docs when chart
  inputs change.

## Testing

The PR workflow in `.github/workflows/testing.yml` does the following:

1. Installs `ct`, Helm, SOPS, and Python support.
2. Installs the `helm-secrets` plugin set.
3. Decrypts any `stable/**/*.enc` fixtures into sibling `.yaml` files.
4. Runs `ct lint --config ct.yaml`.
5. Creates a `kind` cluster when charts changed.
6. Runs `ct install --config ct.yaml` against that cluster.

Mirror that flow locally when validating chart changes:

```bash
ct lint --config ct.yaml
ct install --config ct.yaml
```

If install testing needs encrypted values, ensure the same Helm plugins and
SOPS material are available before running `ct install`.

## Go Code Conventions

- Keep Go helper code confined to `internal/`; this repository does not ship
  standalone production binaries.
- Format with `gofmt` and lint with `golangci-lint`.
- Prefer focused helpers that operate on chart metadata/files rather than adding
  unrelated automation.
- When changing updater logic, preserve the current behavior of scanning chart
  directories, comparing semver-compatible versions, and bumping chart versions
  based on dependency/app changes.

## CI / GitHub Actions

| Workflow | Trigger | Purpose |
|---|---|---|
| `testing.yml` | pull requests to `master` | Run `ct lint`, create a `kind` cluster, and run `ct install` for changed charts |
| `helmdocs.yml` | push to `master`, manual | Regenerate chart READMEs with `helm-docs` and commit the result |
| `release.yml` | push to `master`, manual | Package/sign charts with chart-releaser and push OCI artifacts to GHCR |
| `updates.yml` | daily schedule, manual | Run the internal Go updater and open an auto-merged PR with chart/app version bumps |
| `automerge.yml` | pull requests to `master`, manual | Auto-approve and enable automerge for Dependabot PRs |

## Git & Contribution Conventions

- Use pull requests for all changes.
- Prefer squash merges so chart history stays focused on released changes.
- Security issues → email `security@cloudhippie.de` before opening a public issue.
- Chart publication is automated by `.github/workflows/release.yml`; do not hand-roll release artifacts.

---

## Key Patterns to Follow

1. **Bump chart versions with chart changes**
   - Any functional chart change should be reflected in `Chart.yaml` versioning.

2. **Keep generated docs in sync**
   - If chart metadata, values, or examples change, regenerate the per-chart
     README with `helm-docs`.

3. **Preserve updater annotations and source metadata**
   - `source.yaml` and `# updater: ...` comments in `values.yaml` drive the
     scheduled updater; do not remove them casually.

4. **Match CI when testing installs**
   - Use `ct.yaml`, `kind`, and the Helm plugin/decryption flow from
     `testing.yml` instead of ad-hoc Helm commands when validating chart installs.

5. **Keep org-facing compatibility**
   - Published charts and OCI artifacts are consumed externally; avoid breaking
     repository URLs, chart names, or public README rendering.

## Metadata Changes

When updating `AGENTS.md`, `GEMINI.md`, and `CLAUDE.md`, treat `AGENTS.md` as
the primary instructions file, and `GEMINI.md`/`CLAUDE.md` as copies that
simply reference it (`@AGENTS.md`).

These files are collectively called the "agent instruction files".
